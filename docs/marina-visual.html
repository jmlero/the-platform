Deploy your own agent

Any container that speaks A2A on port 80 is an agent. It runs in the same gVisor sandbox as Marina's own agents and never holds a model key.

  1. Write it

    examples/hello-agent is 100 lines of Go: it reads its model settings from kagent and makes one call per message.

  2. Build and push

    cd deploy/kubernetes/marina-local/examples/hello-agent
podman build -t localhost/hello-agent:v1 .
podman push --tls-verify=false localhost/hello-agent:v1 \
  localhost:5001/hello-agent:v1

  3. Register it

    Two kagent objects in agent.yaml: a Harness (which image) and an AgentTemplate (model and instructions). Apply with kubectl; the image must be pinned by digest.

  4. Talk to it

    In the kagent UI at kagent.localhost:9443, or with the kagent CLI. verify does all four steps for you.

Install on your Mac

An Apple silicon Mac with Podman (8 GB, rootful), plus kind, kubectl, helm, openssl, ruby and python3. One command installs everything; a second proves it works.

# once
podman machine init --cpus 6 --memory 8192 --disk-size 100 --rootful
podman machine start

# 10 to 20 min the first time, about 5 after
python3 scripts/marina-local.py up

# about 1 min, every line says PASS
python3 scripts/marina-local.py verify

Remove it with python3 scripts/marina-local.py down. Your keys and CA stay in ~/.local/share/the-platform/clusters/marina.

Without keys you get the fake model. Add when you want:

Real answers--model-key-file ~/.openrouter-key
OpenRouter, through agentgateway
Agents that change code--github-repo you/repo --github-token-file ~/.github-token --check "npm test" --allowed-path src
Docker instead of Podman--provider docker
