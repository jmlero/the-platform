THE PLATFORM

Deck + Marina / System overview

A control room.
An execution engine.

Deck authorizes and records software work. Marina executes and verifies it. Together, they turn a bounded repository task into a pull request for human review.

The problem → the aim

Agent sessions need supervision and can lose continuity. The aim is to preserve work beyond a laptop session, keep authority explicit, and return evidence you can inspect—on infrastructure you control.

02 /

What makes the execution dependable

Authority belongs to a specific run

A frozen task, scoped credential, run version, and lease fence define permission. Cancellation or expired authority stops new effects; cancellation completes after worker termination is observed.

Recovery starts from durable facts

Marina records intent and checkpoints, then inspects the exact run and Job. Idempotency-Key makes repeated API mutations safe after lost responses.

Completion requires current evidence

Verification checks the changed commit; Marina checks the PR head and required CI. A failed check or requested change becomes a blocker in Deck. Humans control merge and deployment.

03 /

Current focus and proof

Implemented: one bounded repository fix

One operator, one coding Job, separate verification, and a reviewable PR or a clear blocker. Real Deck protocol tests use simulated Git and workers.

Local: Kind + Podman + Calico

The Mac development profile starts with new task intake disabled. Repository/model configuration is still required, and execution depends on the Mac staying awake.

Pending: real installation acceptance

Prove the complete workflow, cancellation, and recovery with the chosen model and Kubernetes installation. The sample supplies no public Ingress.

Long-term aim: an always-on software factory spanning revision, delivery, and operational feedback. Those broader loops remain future work.
