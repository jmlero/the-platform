### Preliminary failures and fixes

The first invocation was cancelled without model work because its installed
allowed paths omitted `tests`; the private configuration was corrected within
the approved repository scope. The initial unavailable-worker case also exposed
the stopped local image registry after VM restart. Startup now restarts only the
existing dedicated registry after starting the local node; its command-order
test passed. No unrelated containers or persistent data were removed.

An early lease case, `tsk_467d834b620bc4e19b5c`, completed normally because its
delay was consumed by chat; it is a healthy repeat, not outage proof. Subsequent
lease cases exposed two real defects: cancellation waited for Deck reads, and
control reconciliation could spend minutes re-reading historical commands while
Deck was offline. Local lease expiry now stops recorded runtime handles before
Deck-dependent work; the main loop calls `StopExpired` before compatibility
checks, and control reconciliation bounds its initial provider-health check.
Failing tests for offline lease expiry and unavailable-provider command scans
passed after these fixes. The final outage row above repeated the experiment on
the final fault build and supplied the passing timing evidence.

The preliminary outage task `tsk_bf3ebc60a8c14a5e7361` was reclaimed once after
Deck expired its lease. That extra run had no approved plan, runtime or model
call; it ended at its budget deadline and counts conservatively against the
12-run allowance. Later outages disabled intake before restoring Deck. The
earlier `tsk_b65d461f6b6968a4d952` proved startup cancellation while Deck remained
offline, but its late stop is not used as timely lease-expiry evidence.
