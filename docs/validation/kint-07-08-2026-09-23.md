## KINT-08 implementation and proof

Marina journals engine state, usage, question identity and answer-send intent.
Deck represents a question as a durable decision tied to the running lease and
exact interaction ID. Options and bounded text answers use the public Deck
contract. Projection recovery uses interaction identity; uncertain answer sends
are reconciled against message history rather than resent. Stale, duplicate,
cancelled and inactive-run answers are rejected. OpenAPI, wire fixtures,
capability discovery, clients and consumer conformance were changed together.

## Reproduction and boundaries

Use the [locked local trial](../../deploy/kubernetes/kagent-trial/README.md),
[governed gateway recipe](../../deploy/kubernetes/kagent-trial/GATEWAY.md),
[BYO Dockerfile](https://github.com/jmlero/the-platform/blob/b7ccd54cdf79f3f669d23c75eb5c9840f43de953/marina/Dockerfile.analysis-byo), and the
[test-only actors](https://github.com/jmlero/the-platform/blob/b7ccd54cdf79f3f669d23c75eb5c9840f43de953/marina/internal/analysisbyo/substrate_live_test.go).
Build the production BYO image from `marina/`. For deterministic live question
and denied-access fixtures, compile the package test binary for Linux ARM64:

```sh
cd marina
CGO_ENABLED=0 GOOS=linux GOARCH=arm64 go test -c \
  -o /private/tmp/kint-question.test ./internal/analysisbyo
```

Layer that binary into the BYO image. Set `KINT08_QUESTION_FIXTURE=1` and run
`-test.run=^TestLiveQuestionActor$`, or set `KINT07_DENIED_FIXTURE=1` and run
`-test.run=^TestLiveDeniedActor$`; allow a bounded test timeout. These fixtures
are not compiled into the production executable. Pin each fixture image digest
and prepare a fresh template revision before selecting its exact profile.
Wait for both template Ready and Deck's advertised profile digest before task
invocation. Do not mutate a harness while its task is running.

The actor trusts `/run/kagent/egress/trust-bundle.pem`. The egress router must
trust Marina's local CA. In this TLS-enabled installation, the trial Service
port 443 targets Marina's named `http` port (8090). Grant `decision.request`
only to Marina in Deck's **actively mounted** service-auth Secret for the trial;
inspect the Deployment rather than assuming an older Secret name is active.
Remove preparation-download egress before invocation, retain selected-source
and model/tool gateway restrictions, and enable only the specific trial task.

Earlier trust/port/checkpoint probes blocked and did not count as successful
acceptance. One denied-source prompt exhausted its budget; another model chose
only allowed reads. Neither establishes denial. A task invoked while Deck still
advertised a replaced profile blocked before execution. Fresh bounded tasks
established the exits above; no failed task was relabeled as successful.

The question is synthetic; full conversational dispatch and inbox UX remain
CHAT/INBOX work. Lost-response, stale/cancelled-answer and invalid-report cases
also have deterministic coverage, but this report does not claim the full live
failure matrix, production authentication, GCP qualification, transparent active
harness recovery, automatic revisions, merge/deploy authority or cutover.
