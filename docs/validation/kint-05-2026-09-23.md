## Implemented boundary

`marina/internal/workresult` now owns the repository/analysis result and check
formats, authorized-path rule and immutable-input validation. The legacy worker
and gateway use this same contract. A successful runtime state alone cannot
advance the workflow: Marina reads the digest-addressed result bytes and checks
stage, source revision, frozen profile/input digests where applicable, observed
time, file scope and mode, duplicate paths, result size, trusted check identity,
command and output digest. It rechecks implementation bytes before publication
and verification bytes before evidence publication. Nonzero check exits remain
truthful observations and block acceptance.

For a kagent attempt, Marina collects the A2A artifacts through the pinned
adapter, reads each stored envelope by digest, checks recorded byte sizes and
accepts exactly one named `marina-result.json` artifact with one inline raw
`application/json` part. KINT-06 also accepts the pinned native Codex harness's
unnamed text artifact only when its complete text is one valid result document.
URLs, mixed parts and free-form text are not result bytes. It
validates the decoded result against the frozen attempt, stores canonical bytes
under a Marina digest, and records an immutable `worker_result` linked to the
same attempt. The original A2A envelope remains in the artifact journal for
provenance. Missing, malformed, duplicate, oversized, out-of-scope or
wrong-revision results block; the engine's completed task state is not evidence.
The legacy result upload route rejects engine attempts, so that path cannot
bypass artifact collection.

The deterministic verifier remains a separate clean-checkout Kubernetes Job.
Its code now has a direct `RunVerification` entry in `worker/verification.go`,
with the shared input types outside the legacy agent runner. The `verify` stage
runs only installed trusted commands at the pinned published
revision, checks that tracked source and HEAD remain unchanged, and returns
digest-bound check output. `TestVerificationChecksThePinnedRevisionInAFreshWorkspace`
passes with a deliberately nonexistent agent harness command, proving this
stage does not launch Codex or the Python analysis agent. The verifier and
legacy worker still share the current image until KINT-12/14. The independent Go
diagnostic-report validator remains separate from the analysis producer.
