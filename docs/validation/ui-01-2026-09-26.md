# UI-01: three-column Deck local acceptance

- Date: 2026-09-26
- Environment: isolated Deck preview on macOS at `http://127.0.0.1:18080`
  with a fresh demo SQLite database, then `kind-marina-local` on
  `podman-machine-default-root` at `https://localhost:8443`.
- Result: the built frontend displayed projects, three work lists, and the
  conversation side by side in both browsers. UI-01 local acceptance passed.

The work list placed active and awaiting-review tasks under In progress,
Backlog and Ready under To do, and reserved Recently completed for accepted,
current results. In the isolated preview, task details opened from the middle
column and Escape closed the drawer with focus restored to the task. Opening
the demo project channel showed the persistent conversation composer in the
right column. The browser view and source checks used the built Deck binary
with its embedded frontend.

The same source was built as a local Deck image and loaded into Kind as manifest
`sha256:8f47bcc1959fe91f3a112c8b564e816367a0bad5083d9df7a930bd048b0cf588`.
Private-overlay preflight passed; Deck rolled out with one Ready replica. After
reload at `https://localhost:8443`, the browser showed Projects, In progress
(52 tasks), To do (11 tasks), Recently completed, and the project conversation
with its composer simultaneously. Opening a Ready task from the middle column
showed the task drawer; closing it returned focus to that task. This also
exercised the existing populated project rather than only demo data. No tasks
were changed by the browser check.

`npm test` passed all 28 frontend tests. `npm run check` reported zero errors
and warnings. `make -C deck build` passed and refreshed the embedded bundle.
The grouping test covers awaiting review, stale evidence, ready-first ordering,
and newest-first completed results. Recently landed remains a later label
change after LAND-01 lands changes on main.
