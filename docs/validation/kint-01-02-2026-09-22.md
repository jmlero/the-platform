- Date: 2026-09-22
- Result: KINT-01 and KINT-02 acceptance passed within the local trial scope.
- Environment: ARM64 Mac, `podman-machine-default-root`, `kind-marina-local`,
  Kubernetes `v1.37.0`, node `marina-local-control-plane`, 8 GiB Podman VM.
- Repository baseline: `d229c86763e18263de6b855b7e487d4db65572d7` plus the

## KINT-01 lock and ownership

The [lock](../../deploy/kubernetes/kagent-trial/lock.json) records the exact source
commits, chart archives and OCI identities, sixteen ARM64 image references,
CLI hashes, public API versions, gVisor release asset, transitive source-manifest
hashes, disabled chart dependencies and license inventory. Each selected image
had a Linux ARM64 manifest. The source-based [removal inventory](../plans/kagent-integration.md#removal-inventory)
identifies symbols, callers, retained behavior, current tests and deletion gates.
No legacy implementation was removed.

The published chart archives include their dependency lock. kagent and Substrate
sources are Apache-2.0; the Substrate `_LICENSES` bundle contains 268 files and
has a recorded tree digest. PostgreSQL retains its own license. Redis is not a
dependency of this pinned Substrate chart, despite older website descriptions.
The source locks and image digests preserve transitive versions; this work does
not claim a full image SBOM or legal clearance for redistribution.

The [installation guide](../../deploy/kubernetes/kagent-trial/README.md) documents
authentication, egress, privileged host requirements, storage, reproducible
render/install commands and cleanup. The [cluster inventory](../../deploy/kubernetes/kagent-trial/cluster-resources.json)
contains the statically rendered objects; three runtime-generated signer trust
bundles are separately described in the guide.

## Preparation and compatibility findings

1. Baseline `make -C marina check` passed after rerunning with local socket
   access; the sandboxed first attempt could not bind test sockets.
   `make check-installation` passed before changes (11 tests).
2. The default Kind API served stable certificate `v1`. Substrate beta4 requires
   the beta certificate client API. Its absence was reproduced by the read-only
   preflight, then resolved by enabling only
   `certificates.k8s.io/v1beta1=true` in the API-server runtime configuration.
   The saved original manifest was restored after the trial. No cluster
   recreation or storage migration occurred.
3. The renderer produced 85 trial resources with digest-pinned images, optional
   tools/UI disabled, bounded resource settings and narrowed RBAC. The initial
   upstream two-replica Substrate API was reduced to one; the final renderer
   reproduces that setting.
4. Generated CA/JWT pools stayed in trial namespaces. The existing operator,
   Git and model credentials were not supplied to the trial. Native Codex
   required `openAI.apiFormat: responses`, an exact DNS hostname and a Secret
   reference. The final fixture used `no-inference.invalid:9` and a random
   nonfunctional credential. **No model calls or external repository writes
   were performed.**
5. The node agent prepared the locked gVisor release, pause image and native
   Codex image during a separate download phase. Its temporary internet-egress
   policy was removed before instance creation and restart/restore proof.
   Runtime restore used the retained cache and in-cluster RustFS snapshots.

## Live lifecycle and isolation

The native Codex template became Ready after gVisor booted its golden actor and
wrote a full snapshot to RustFS. The prepared revision was
`77430262edbe3ecf5df35eb9da526ea479bd49480b74810e3ef25619d11ce5a5`.
One public `CreateAgentInstance` call used the recorded key
`kint-02-lifecycle-20260922` and returned instance
`01a0c90f-421c-7722-a948-0827651d1aed`.

The trial replaced kagent's controller/PostgreSQL, Substrate API/controller/
PostgreSQL, atelet and the worker. RustFS was stopped to zero replicas before
replacement to avoid overlapping writers. After recovery, replaying the original
creation key returned the same instance ID, context ID, prepared revision, route
and creation time. Administrative Substrate resume then restored the actor from
the retained full snapshot on the replacement worker; it reached
`ACTOR_STATE_RUNNING` and suspended successfully afterward. These are synthetic
engine-administration operations, not newly supported Marina commands.
See the redacted [lifecycle record](kint-01-02-lifecycle-2026-09-22.json).

Two temporary, token-free probe Jobs completed successfully:

| Check | Authorized probe | Worker-policy probe |
| --- | --- | --- |
| Engine controller TCP 8083 | Allowed | Denied |
| Internet TCP 443 (`1.1.1.1`) | Denied | Denied |
| Kubernetes service TCP 443 (`10.96.0.1`) | Denied | Denied |
| Deck service TCP 8080 | Denied | Denied |
| Mounted Kubernetes service-account token | Absent | Absent |

The allowed controller probe establishes a positive network control. RBAC
impersonation checks denied Substrate credential-reader access to
`marina-system` Secrets and denied Substrate controller mutations of its
Deployments. NetworkPolicy isolates Pod traffic; the privileged substrate
infrastructure and node administrator remain trusted. These probes do not
replace the per-attempt model/tool/source authority tests required by KINT-04.

## Resource sample

The [resource record](kint-01-02-resources-2026-09-22.json) contains a kubelet
statistics sample, not a load test:

- Trial Pod working set: **353.1 MiB**; aggregate CPU: **0.050 cores**.
- Whole-node working set: **2518.8 MiB**, versus **1800.7 MiB** in the earlier
  baseline. This includes cache/system effects and is not an isolated benchmark.
- Trial PVC requests: **2.5 GiB** (two PostgreSQL stores and RustFS). Local-path
  requests are not filesystem usage limits.
- Measured ateom preparation cache: **652,684 KiB** (about **637.4 MiB**),
  excluding containerd image storage. Cached preparation assets were retained.
- Main control-container requests in the final render total 1.1 CPU and
  1344 MiB, before the worker (250m/512Mi), restartable PostgreSQL TLS sidecar
  and temporary setup/probe Jobs.

This establishes room for the bounded local lifecycle exercise. Full Codex/BYO
workload peaks, image footprint and snapshot growth remain KINT-10 measurements.

## Teardown and verification

The actor was suspended, the WorkerPool removed while its controller still ran,
and all three trial namespaces deleted. Namespace finalization exceeded the
initial 45-second wait; it completed normally without forcing finalizers.
The inventoried trial CRDs, RBAC, PriorityClass, admission policy/binding,
SandboxConfig and generated signer trust bundles were removed. The Kubernetes
API-serving trust bundle was preserved. Trial port-forwards were closed.

The original API-server manifest was restored only after comparing the current
file to the expected single-argument edit. Kubernetes `/readyz` returned `ok`;
Deck returned HTTPS **200** at `https://localhost:8443`. Both original Deployment
UIDs and complete specs were unchanged and Ready. Both Platform PVC UIDs and
bound-volume identities were unchanged. No labelled trial resources remained.
See the [teardown record](kint-01-02-teardown-2026-09-22.json).

Final checks: seven new focused render/install safety tests and all 18
installation tests passed; `git diff --check` passed. The focused tests were
written failing first and then passed with the implementation. The live proof
used real kagent/Substrate processes on local Kubernetes. No Deck/Marina contract
was changed, so root conformance was not rerun for this installation-only change.

KINT-03 onward must implement governed dispatch, fencing/budgets, evidence,
both actual workloads, failure acceptance, upgrade/rollback and legacy removal.
The trial's isolated unauthenticated kagent API, synthetic identity and no-model
fixture are not a production authentication or governed-workflow claim. The
alpha's database upgrade semantics, Python/BYO snapshot behavior and native
Codex gateway compatibility remain explicit later gates.
