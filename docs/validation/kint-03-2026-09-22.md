# KINT-03: engine lifecycle and durable correlation

- Date: 2026-09-22.
- Scope: the pinned kagent adapter at Marina's existing runtime boundary.
- Environment: ARM64 Mac, `podman-machine-default-root`, `kind-marina-local`,
  Kubernetes 1.37.0; the isolated KINT-01/02 topology was temporarily reinstalled.
- Source: `03b986eb5c659a5532f0dca46a43f22b1f8adf99` plus the final KINT-03
  working-tree cancellation, interaction-correlation and evidence changes.

## Implemented boundary

[`internal/kagent`](../../marina/internal/kagent/README.md) implements start,
recorded-key lookup, inspection, cancellation observation, artifact collection
and cleanup using public lifecycle and A2A gRPC APIs. It does not read engine
stores or import engine internal packages. The exact kagent source commit is
`850c464726881317997c32515f8b621b949d6ce1`, with A2A Go v2.5.0 and the locked
Substrate v0.2.0-beta4 module replacement.

The immutable runtime specification binds backend/version, endpoint,
harness/template, expected revision, profile and context digests. An additive
SQLite migration retains instance route/revision and A2A context, message and
task identities. Version-guarded updates reject changed correlations. Creation
intent and message-send intent are separate, and survive reopening the journal.

Creation retries replay the recorded request key. A returned revision mismatch
blocks before task delivery; the idle instance remains recorded for cancellation.
An uncertain message is resolved through exact stored message/task lookup, never
by sending replacement work. Missing tasks or identities produce explicit
blockers. Pending interactions retain task identity but do not enable resume or
question/answer continuation.

Cancellation persists intent before deleting the exact instance and requires a
subsequent authoritative absence observation. A failed or lost delete response
does not itself acknowledge cancellation. Collected output envelopes are bounded,
digest-bound local artifacts and survive idempotent cleanup. They are unverified
outputs; engine completion is not Marina workflow completion.

## Deterministic evidence

The behavior tests were written failing before their corresponding fixes. They
use real SQLite reopen/recovery and the upstream generated gRPC wire types with
an in-memory deterministic server:

- Lost successful creation and accepted-message responses recover one original
  instance/task; message dispatch occurs once across journal reopening.
- An unknown delivery stays inspect-only and never resends.
- A different prepared revision receives no task.
- Cancellation waits for deletion, recovers a lost deletion response, and can
  clean up an uncertain create without sending work.
- Changed or missing instance identities block; no replacement is created and
  no unexpected identity is deleted.
- Correlation changes and stale journal writes are rejected.
- Completed output bytes remain inspectable after cleanup and journal reopening;
  cleanup cannot delete normal results before collection.
- Engine cancellation status triggers termination observation rather than being
  accepted as proof; input-required tasks retain their exact task identity.

## Live local evidence

`TestLiveIsolatedLifecycle` ran against the real pinned controller, PostgreSQL
and Substrate processes through authenticated Kubernetes port-forwarding on
`127.0.0.1:18083`. The trial retains its isolated unauthenticated engine API;
`x-user-id` is a synthetic caller partition, not authentication. Runtime
preparation egress was removed before the test.

The first successful `CreateAgentInstance` response was deliberately discarded
by a client interceptor. After closing/reopening SQLite and replacing the gRPC
connection and adapter, replay returned the original instance:

| Context | `716e70e5-6035-4410-8d08-c70e880a691e` |
| Message | `marina-rtm_09e081eec814d61a4bd161be` |
| Route | `ai-01a0c938-8731-701c-9a7b-a40b545d0842.kint-engine.actors.resources.substrate.ate.dev` |

Message delivery was interrupted **before engine admission**, respecting the
fixture's no-inference authorization. Repeated real task-history lookups returned
the explicit unknown-delivery blocker, with one send attempt and no resend.
No live A2A task was created and no model call was made. Accepted-message/task-ID
recovery is deterministic evidence above, not live native-harness execution.

The successful real delete response was then discarded. After another journal
and connection replacement, the adapter observed `NotFound`, returned cancelled,
collected the empty cancellation output set and completed cleanup. Replaying
start after cleanup did not recreate the instance. The two creation RPCs mapped
to one instance, and no replacement message or instance was created.

This proves adapter journal/connection reconstruction, not a Marina deployment
rollout or a crash during active harness I/O. KINT-02 separately proved engine
component replacement and native snapshot restore. The remaining live workload
failure matrix belongs to KINT-09.
