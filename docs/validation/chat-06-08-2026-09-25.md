- Status: implementation and deterministic contract proof passed; installed actor and browser acceptance pending

## Implemented boundary

The conversation actor returns an answer and, only for a concrete request, a
structured task interpretation. It cannot supply a budget, grant, project, or
repository profile. Marina freezes the published reply and task request in its
journal before calling Deck. A lost response replays the same request after
restart. Clear execution intent can create Ready work only when Marina has an
explicit fixed repository delegation budget and the current installed profile
digest. Otherwise the task is a Backlog draft. Deck separately gates Ready
delegation by service capability, project grant, installed `repository/v1`
profile, acceptance criteria, exact two-attempt budget, and repository authority.
It creates the reply, task, origin link, and replay record in one transaction.

Deck projects selected run, decision, and command milestones into the originating
thread in the event transaction. Completion links the current verification
artifact and evidence IDs; blockers remain visible. The task ledger and its
evidence stay authoritative. A later explicit change request can create a new
task linked to a completed task in the same thread. The original task and result
remain unchanged. Replaying a published outcome returns the same message and
task IDs; changing it conflicts. Outcome records survive Deck export/import.
