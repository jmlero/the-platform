# MAR-01 to MAR-09: Marina's platform API, with Deck and the CLI as clients

- Date: 2026-10-17 and 2026-10-18
- Environment: the developer Mac for deterministic and real-process checks; local
  Podman/Kind, explicit `kind-marina-local` context on `podman-machine-default-root`,
  for the kubectl proof
- Decision: [0033](../decisions/0033-marina-platform-api.md); plan:
  [Marina platform API](../plans/marina-platform-api.md); contract:
  [marina/api](../../marina/api/README.md)
- Result: Marina serves `marina.dev/v1` over HTTP/JSON and as Kubernetes
  resources, from its own ledger. Deck and `platformctl` are clients, Marina
  calls no client, and Deck serves no route for Marina. All product and
  real-process checks pass. The installed local release still runs the earlier
  Deck-provider pair until the cutover (MAR-10). No model was called and no
  repository was changed.

the repository and conversation workflows. It proves the API, identity,
controller, ledger and clients, not engine, model, Git or CI behavior; those keep

## By task

- **MAR-01 API design.** `marina/api/openapi.yaml`, generated CRDs and 11
  fixtures. `go test ./api` validates every fixture against the OpenAPI schema
  and the CRD schema, and rejects engine and sandbox names. Operator review of
  the design is still open.
- **MAR-02 Kubernetes identity.** TokenReview and SubjectAccessReview with a
  short cache; Roles `marina-viewer`, `marina-factory`, `marina-admin` and the
  controller's ClusterRole. Tests cover allowed, denied, anonymous and
  wrong-namespace requests. On Kind, a real service account token bound to
  `marina-factory` in `factory` could list and create Runs there, got 403 in
  `default`, and `kubectl auth can-i` showed no write access to status or
  Workloads. The creator is recorded in `marina.dev/created-by`.
- **MAR-03 Marina-owned runs.** Migration 016 adds the platform ledger; it
  implements every work-control port in process. Tests cover a changed spec
  conflicting, replay, dependencies, plan approval and change requests,
  completion only with passed independent evidence, cancel, ordered events
  across restart, and restart renewing the exact run without a new claim.
- **MAR-04 controller.** Projects, Workloads, Runs, Turns and Decisions
  reconcile into the ledger and mirror status; deleting a Run cancels it
  through the `marina.dev/cancel` finalizer.
- **MAR-05 factory choices.** Workload choices are frozen per run and applied
  to the workflow; a profile without review and one with review both run, and
  choices cannot exceed the installation's limits.
- **MAR-06 turns and decisions.** Reply, clarification and proposal round trips
  pass over HTTP and through resources.
- **MAR-07 contract tests.** The sandbox build is the real process every client
  tests against; root `make conformance` runs it for Deck and the CLI.
- **MAR-08 Deck as a client.** Deck creates a Run for each Ready task and a Turn
  for each chat invocation, recording the exact spec first so a lost response
  replays. It mirrors status, plans, decisions, evidence and landing through
  its existing validated transitions, forwards answers and cancels to Marina,
  and proxies artifacts. All service-identity routes, `requireService`, the
  provider endpoints and the demo agent are removed. Deck's conformance covers
  plan approval to landing with evidence, a blocked run with its reason,
  cancel, a Deck restart mid-run with exactly one Marina Run, chat reply,
  clarification answered in Deck, and a proposed Backlog task. The browser
  suite covers chat, clarification, plan approval to the landed result, and
  cancel. Two PRD browser tests and the legacy review-acceptance browser test
  moved to store and HTTP tests because the sandbox does not produce PRDs.
- **MAR-09 `platformctl` and `kubectl`.** New commands `capabilities`, `runs
  create|list|get|events|cancel`, `turns create|get` and `decisions
  list|answer`. Against the sandbox, the CLI created a Run, replayed it,
  approved the plan, followed events to `Succeeded`, showed review,
  verification, ci and landing evidence and the landed commit, cancelled a
  second Run and got a chat reply; an anonymous call failed with 401. On Kind,
  `kubectl apply` created a Project and two Workloads (both reported
  `Ready`/`Accepted`), `kubectl create` submitted a Run, `kubectl patch` set the
  plan Decision's `spec.response`, and `kubectl wait` saw `Succeeded` with four
  passed evidence records and the landing commit. `kubectl delete` of a waiting
  Run removed it and the ledger recorded `run.cancel_requested` and
  `run.cancelled`.

## Cleanup on Kind

The test namespaces `factory` and `factory-default`, the test service account
and its binding, and the four ClusterRoles and one ClusterRoleBinding were
removed. The five `marina.dev` CRDs remain installed with no resources; the
cutover installs them anyway. The installed Deck and Marina were not changed.
