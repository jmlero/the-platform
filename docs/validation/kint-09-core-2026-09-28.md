## Fixed during the run

- **Completion of longer tasks.** Codex tasks over about 30 seconds never
  completed: the pinned controller records a task's progress only while a send
  or subscription is open. Sends now return immediately, and Marina follows an
  unfinished task on every observation (commit `cd1cca4`, before these cases).
- **Worker restarts.** Restored golden actors could not pull their harness image;
  a permanent `atelet-local-registry` policy and the local registry fix this
  (commit `b7558a5`).
- **Mistyped base64.** Two of the nine native results with file changes on
  28 September before this fix,
  `exec_73c57b4fad796c4d2970d79f` and `exec_ea08e8caa8cc8088896d5419`, carried
  file content whose base64 the model had mistyped. Marina rejected both and
  blocked. The native prompt now asks for each file as UTF-8 `text`, which the
  result parser turns into the same bytes; base64 `content` remains for files
  that are not text. The create, send and CI reruns used this build.
- **Answer after a lost response.** An answer sent with ReturnImmediately left the
  controller storing the task as waiting for input, and a subscription to such a
  task never reaches the engine. Chat turn `msg_03d986de6600925b856d` therefore
  blocked at its deadline after its answer's response was lost. Answers are now
  sent without ReturnImmediately; the [chat report](chat-04-10-2026-09-28.md)
  records the recovered rerun.

## Remaining limits

These are recorded in the backlog, mainly under KINT-17:

- A lost worker is noticed only at the task deadline.
- A budget block names the failed engine task; the budget reason is the
  `model.budget_exhausted` event in the task timeline.
- A task whose change is already on main blocks as an invalid result.
- The Codex harness image has no Node.js, so the implementer cannot run the
  checks itself; the verification Job and CI do.
