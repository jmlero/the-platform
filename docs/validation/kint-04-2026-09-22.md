## Implemented controls

The kagent adapter now requires a current admission implementation before
instance creation and message delivery, including recovery. `workerapi.Server`
implements it using the existing persisted specification, Deck run/fence/lease,
context validator, deadlines and durable budget totals. A missing admission or
context validator fails closed. Observation and cancellation remain available
without new authority. No new task intake or workload backend was enabled.

The HTTPS-only `/engine/` routes decode an attempt selector plus the existing
specification HMAC from the injected Bearer credential. Model, input, authority,
read-only Git and selected-context requests reuse the existing handlers. Engine
calls also require durable `sending`/`active` state. Cancellation/deletion intent,
terminal state, credential expiry, current-fence failure, context revocation or
provider unavailability denies subsequent calls. Active model/source connections
reuse the two-second revalidation loop; this is bounded polling, not instantaneous
termination of an already admitted provider operation.

Model reservation checks engine cancellation and credential expiry inside the
SQLite transaction as well as at HTTP admission. Every retry obtains a separate
attempt-correlated reservation. Known terminal usage is charged; uncertain calls
retain their full token/cost reservations across restart. Existing execution
budgets still bound all calls and prevent overspending through retries.

A governed specification names exactly one credential reference:
`secret://<engine namespace>/<attempt-exclusive template>/gateway`, expiring no
later than the attempt. The journal rejects a second attempt using the same
endpoint/namespace/template even after cleanup. This prevents template Secret
rotation from giving an old instance a later attempt's credential. Names must not
be recycled and one installed engine must retain its canonical endpoint identity.
Installed workflow provisioning and prepared-resource inspection remain required
before dispatch. The isolated live fixture below performs those steps manually.

## Native protocol compatibility

The pinned translator renders `web_search = "cached"`; an actual Codex 0.148.0
App Server request nevertheless included
`{"type":"web_search","external_web_access":true}`, along with
`client_metadata`. Passing that request unchanged fails Marina's restricted
model contract.

For engine repository calls, the gateway removes this exact web-search tool
announcement and drops transport-only client metadata before validation and
forwarding. It does not grant search access. Explicit remote tool choices,
other search shapes, remote MCP/provider tools, stored prompts/conversations,
background execution and unknown top-level Responses fields remain denied.
Analysis retains its own strict frozen tool allowlist. No MCP service or new
agent tool was added: the selected BYO workload can use the existing HTTP context
read when KINT-07 installs it.

`TestNativeCodexGateway` ran the real binary copied from the cached image layer
of the locked kagent Codex image on `kind-marina-local`, using
`podman-machine-default-root`. Version output was `codex-cli 0.148.0`.
It exercised the native App Server initialization, thread/start and turn/start
sequence with the pinned translator's relevant configuration, including the
search default. A generated CA and signed loopback TLS certificate secured the
real gateway connection. A synthetic TLS Responses upstream returned one complete
stream. The native turn completed; the gateway charged exactly **3 fixture
tokens**, with **0 pending reservations**. The test also asserts that search and
client metadata never reach the upstream.

The test ran in a disposable Alpine container with `--network none`, read-only
root, all capabilities dropped, no-new-privileges, UID 10001, a temporary `/tmp`
and read-only fixture binaries. It had no real provider/Git credentials,
Kubernetes token or repository mount. All HTTP traffic stayed on its loopback.
No paid model call, external source call, GCP change or Kubernetes deployment
occurred. The container was removed automatically. Test binaries remain outside
Git under `/private/tmp/kint04-native`.

This is **real native Codex and HTTPS**, with synthetic provider/Deck responses
and a real SQLite journal. It is **not** a live kagent/Substrate invocation,
credential-injection/cache test, or a network-policy proof for the installation.
The test supplies an attempt-scoped gateway credential directly to the native
client; actual Substrate injection must keep even that credential outside the
agent process. KINT-02's prior lifecycle/isolation evidence does not replace this
separate Substrate acceptance below.

### Installation findings and corrections

The credential provider's trial namespace policy was empty. It denied the real
native request with `atespace "kint-engine" is not permitted to resolve secrets
in namespace "kint-engine"`, despite Ready templates and correct Secret RBAC.
`substrate-values.yaml` now grants exactly that same-namespace mapping. The
rendered policy was inspected, the isolated provider restarted, and the same
native path passed. No other namespace or product's Secret access was added.

The synthetic gateway initially used Service port 8443. The pinned router
presented its outer TLS listener on that destination; native Codex and independent
TLS probes rejected it. Changing the Service to **443 → container 8443** passed
with the original native harness and genuine TLS verification. An experimental
`CODEX_CA_CERTIFICATE` override did not resolve the port failure and was removed.
The egress router trusts only the generated test CA for the synthetic destination;
the actor trusts the projected Substrate MITM CA. No TLS verification was disabled.
