# Marina Helm chart

Installs Marina and its `marina.dev/v1` API on any Kubernetes cluster, with no
Deck or other client ([decision 0033](../../../../docs/decisions/0033-marina-platform-api.md),
contract in [marina/api](../../../api/README.md)). Clients such as Deck,
`platformctl` and `kubectl` use the API with their own Kubernetes identities.

The chart installs the CRDs (from `crds/`, generated by `go test ./api -update`),
Marina's Deployment, Service, service account and controller ClusterRole, the
client roles `marina-viewer`, `marina-factory`, `marina-admin` and `marina-capabilities`, the worker
namespace with its Job RBAC, quota and network policy, and Marina's network
policies. Helm installs CRDs only when they are missing and never upgrades or
deletes them; apply `crds/` yourself after an API change.

It does not create Secrets or the workflow configuration. Before installing,
create in the release namespace:

| Object | Content |
| --- | --- |
| ConfigMap `workflow.configMap` | `workflow.json`: the installed execution profiles; see the [first-release guide](../../../../deploy/kubernetes/first-release/README.md) |
| Secret `secrets.credentials` | The token files `workflow.json` names under `/run/marina-secrets` |
| Secret `secrets.artifactAuth` | `token` for Marina's artifact store |
| Secret `secrets.tls` | `kubernetes.io/tls` certificate for `marina.<namespace>.svc` |
| ConfigMap `trust.caConfigMap` | `ca.crt` trusted for outbound TLS, also mounted by workers |

## Install

```sh
helm upgrade --install marina marina/deploy/helm/marina -n marina-system \
  --set image.digest=sha256:... -f my-values.yaml
```

Then create one namespace per project with its `Project` and `Workload`
resources ([example](../../../../deploy/kubernetes/first-release/factory.example.yaml))
and bind each client to a role there. New work waits until
`intake.enabled=true`; `intake.runID` admits a single Run.

## Options

| Value | Default | Purpose |
| --- | --- | --- |
| `image.digest` / `image.tag` | unset | Prefer an immutable digest |
| `intake.enabled`, `intake.runID` | `false`, unset | Admit new Runs |
| `persistence.existingClaim` | unset | Reuse a journal volume; otherwise a 1 Gi claim kept on uninstall |
| `networkPolicy.clients` | `[]` | Pods that may call the API, as NetworkPolicy peers |
| `networkPolicy.egress` | `[]` | Site egress: Kubernetes API server, Git and model hosts |
| `hostAliases` | `[]` | Pinned host addresses for the egress rules |
| `workers.namespace`, `workers.createNamespace` | `marina-workers`, `true` | Worker Jobs |
| `platform.engine.enabled` | `false` | kagent engine RBAC and network policy |
| `platform.telemetry.otlpEndpoint` | unset | Export traces (PLAT-09) |

The model gateway, ingress and policy components keep their own manifests under
[deploy/kubernetes/platform](../../../../deploy/kubernetes/platform/README.md),
including their side of Marina's network policy. Run one replica only: the
journal is SQLite on a ReadWriteOnce volume.

`scripts/test_marina_chart.py` checks the rendered chart (set `HELM` to the Helm
binary). The local profile's move to this chart is in
[local-podman-helm](../../../../deploy/kubernetes/local-podman-helm/README.md).
